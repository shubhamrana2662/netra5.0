## 1. Output Classification Taxonomy

Every field and output generated by CyberDrishti AI must carry an explicit epistemic classification to ensure investigators and court authorities understand its evidential status:

| Classification | Definition | Example in CyberDrishti AI | Court Evidentiary Weight |
|---|---|---|---|
| **`OBSERVED`** | Direct, unmanipulated forensic record extracted verbatim from submitted media. | Call timestamp `2026-04-22 11:18:00` from CDR; bank statement debit row. | Primary evidence (BSA Sec 63 / IEA Sec 65B certificate required). |
| **`DERIVED`** | Deterministic mathematical or rule-based calculation from observed records. | Call duration in seconds; account balance delta; regex-extracted IFSC code. | Corroborative evidence; provably deterministic. |
| **`INFERRED`** | Rule-governed heuristic or domain correlation across multiple observed sources. | Associating a caller with an IMEI when CDR and chat bracket the exact time. | Investigative lead; requires officer confirmation. |
| **`PREDICTED`** | Probabilistic machine learning model output with associated confidence interval. | Hidden link between mule accounts via topological logistic regression; HingBERT NER tag. | Investigative lead ONLY; NEVER admissible as sole proof. |
| **`APPROXIMATED`** | Statistical aggregation or interpolated data subject to measurement error. | Tower triangulation rough coordinate radius; estimated total syndicate revenue. | Informational context only. |
| **`UNKNOWN`** | Missing, ambiguous, or unverifiable attribute where data was insufficient. | Undetermined caller identity for burner SIM; untracked crypto mixer hop. | Explicitly abstained; zero hallucination. |

## 4. Legal, Privacy, and Admissibility Guidelines

1. **Section 63 BSA (erstwhile 65B IEA) Admissibility**:
   - Every piece of digital evidence must record its SHA-256 hash immediately upon byte ingestion.
   - The storage path must be immutable, and processing must verify the SHA-256 hash prior to parsing.
   - Output reports must include device provenance, server hostname, software version, cryptographic hash, and chronological timestamps.
2. **DPDP Act 2023 Compliance**:
   - Forensic processing of personal data for prevention, detection, or investigation of offenses is covered under Section 17(1)(c) exemptions.
   - However, data minimization mandates that innocent decoy entities (e.g. non-suspect family members in chat logs) must not be propagated to inter-case intelligence databases.
3. **Aadhaar Masking**:
   - First 8 digits of any 12-digit Aadhaar number extracted via OCR must be masked (`XXXXXXXX1234`) in UI representations and reports.
4. **Investigative Independence**:
   - Predictive models (such as Hidden-Link probabilities) must be explicitly marked as leads for verification, never as conclusive findings.
